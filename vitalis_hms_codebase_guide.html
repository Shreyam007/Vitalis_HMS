1. System Architecture & Tech Stack OVERVIEW

Vitalis HMS is built using a modern decoupled MERN architecture featuring modular role-based wards (Patient Ward, Doctor Ward, Admin Ward), real-time Server-Sent Events (SSE), and a clinical graph design system.

Layer Technology Primary Responsibility Root Path
Client Application React 18, Vite 6, TailwindCSS, React Router 6 Single Page Application with 18 ward routes & live SSE dispatching client/
Backend Server Node.js, Express, Multer, JWT, SSE EventBus REST API controllers, SSE broadcast channels, Multer file storage server/
Database Layer MongoDB Atlas (Mongoose ODM) + Local Fallback Cloud document persistence for 9 clinical data schemas server/models/
Real-Time SSE Express EventBus (In-Memory Publisher/Subscriber) Broadcasts queue:update and invoice:paid events server/sse/eventBus.js

4. State Management & Real-Time SSE REACT CONTEXT & EVENTBUS

1. Authentication Context client/src/context/AuthContext.jsx Lines 1 - 85

Manages active user state, JWT access token in localStorage, role verification, and login/register methods.

const [user, setUser] = useState(null);
const [token, setToken] = useState(localStorage.getItem('vitalis_token') || null);

// Key methods exposed via useContext(AuthContext):
// - login(email, password)
// - registerPatient(formData)
// - logout()
2. Real-Time Server-Sent Events Hook client/src/hooks/useSSE.js Lines 1 - 25

Opens a persistent HTTP connection to /api/events?token=.... Automatically dispatches incoming events (queue:update, invoice:paid, prescription:issued) to React components without polling.

3. Server EventBus Channel server/sse/eventBus.js Lines 1 - 35

In-memory publisher/subscriber mapping connected response clients. Supports targeted single-user emit via emitToUser(userId, event, payload) and global broadcasts via broadcast(event, payload).
